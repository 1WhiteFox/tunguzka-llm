## Что такое Tunguzka-LLM?

**Tunguzka-LLM** — это ультракомпактный независимый движок инференса трансформеров (архитектуры LLaMA, SmolLM, BitNet b1.58), созданный с нуля специально для ретро-компьютеров конца 1990-х годов.

Движок не использует сторонних математических библиотек (включая `libm`), обходится без динамических аллокаций памяти во время генерации токенов (статическая `MemoryArena`) и не содержит ни одной инструкции поколения $i686+$ (`CMOV`, `FCOMI`, `SSE`). Благодаря технологии послойного дискового стриминга (**Layer-Major Streaming**) движок способен запускать модели, физический размер которых многократно превышает объём установленной оперативной памяти (на машинах с 16–32 МБ ОЗУ).

## Статус проекта, дисклеймер и открытость

* **Экспериментальный статус и отсутствие гарантий:** Проект создаётся исключительно как исследовательское хобби в свободное время. Никаких гарантий стабильности, идеальной точности генерации или безотказной работы на всём многообразии материнских плат, чипсетов и ретро-BIOS предоставить невозможно. Всё распространяется по принципу *«как есть» (AS-IS)* — запуск производится на ваш страх и риск.
* **Непрофильный бэкграунд:** Автор проекта — энтузиаст из непрофильной сферы (бизнес-информатика), а не профессиональный системный инженер низкого уровня или разработчик компиляторов. Многого обещать не могу: разработка ведётся исключительно по мере сил, вдохновения и свободного времени. Ожидать круглосуточной техподдержки, мгновенного исправления issues или закрытия всех краевых случаев не стоит.
* **Планы на обновления:** До конца года запланирована пара точечных апдейтов — полировка стабильности, исправление выявленных узких мест и небольшие оптимизации.
* **Использование ИИ (AI Transparency):** Общая архитектура движка, идея послойной укладки слоёв для дискового стриминга (Layer-Major), формат картриджей `.mmx v2` и системные решения придуманы автором. При этом в процессе написания кода и поиска багов активно и открыто использовались нейросети (LLM) — как интерактивный ассистент для парного программирования, помощи с ассемблерными вставками и дебага синтаксиса C99.

## Ключевые архитектурные особенности

### 1. Четыре аппаратных вычислительных бэкенда (`-b`)
* **`3dnow` (AMD K6-2 / K6-III / ранние Athlon):**
  * Параллельное векторное умножение матриц сразу по 2 строкам с использованием регистров MMX и расширений 3DNow!.
  * Аппаратное упреждающее чтение кэш-линий под 32-байтный L1-кэш (`prefetch 32`).
  * Прямая векторная конвертация упакованных целых чисел в числа с плавающей запятой в обход медленного блока x87 FPU (`pi2fd`).
  * Векторное масштабирование и сложение через `pfmul`, `pfadd` и горизонтальное суммирование `pfacc`.
  * Аппаратно ускоренное вычисление обратного квадратного корня для `RMSNorm` на конвейере `pfrsqrt`, `pfrsqit1` и `pfrcpit2`.
  * Мгновенный сброс состояния регистров FPU/MMX инструкцией `femms` без штрафных тактов.
* **`mmx` (Intel Pentium MMX / P55C):**
  * Спаренные SIMD-ядра `pmaddwd`, выровненные под двухпоточный суперскалярный конвейер (U/V) процессора P55C.
  * 2-килобайтная таблица поиска для тернарных весов (`g_ternary_lut`), гарантированно умещающаяся в L1D-кэше процессора.
  * Распаковка 4-битных нибблов весов Q4 на битовых сдвигах и логических масках без дополнительных обращений к памяти.
  * Батчинг матричных строк блоками по 16 штук для амортизации накладных расходов барьера перехода `emms`.
* **`p54c` (Intel Pentium Classic, процессоры без поддержки MMX):**
  * Двухпоточные алгоритмы SWAR и целочисленные таблицы поиска, работающие исключительно в 32-битных регистрах общего назначения (`EAX`–`EDX`).
* **`scalar`:**
  * Переносимый эталонный C99-бэкенд для отладки и верификации точности.

### 2. Формат картриджей весов `.mmx v2`
* **Послойная укладка тензоров (Layer-Major Layout):** Внутри каждого слоя тензоры упакованы строго в хронологическом порядке их вызова в прямом проходе (`wq -> wk -> wv -> wo -> w1 -> w3 -> w2`). Это гарантирует строго последовательное чтение файла и устраняет перемещения магнитной головки старых IDE-дисков при стриминге.
* **Контроль целостности:** Заголовок размером 64 байта защищён контрольной суммой IEEE 802.3 CRC32 и хранит точный параметр эпсилон нормировки $\varepsilon$, смещение встроенного словаря и тип функции активации (`SwiGLU` или $\text{ReLU}^2$).
* **Профили квантизации:**
  * `binary`: 1.0-битные упакованные веса (8 весов на байт).
  * `ternary`: 1.58-битные веса BitNet b1.58 (2 бита на код, 4 кода на байт).
  * `q4`: 4-битное симметричное квантование со смещением 8 (2 веса на байт).
  * `q8`: 8-битное симметричное целочисленное квантование.
  * Гибридный режим с сохранением матриц эмбеддингов и выходного классификатора в формате Q8 для минимизации потерь перплексии.

### 3. Подсистемы памяти и кэширования
* **Сэмплинг без кучи (Zero-Alloc Stack Sampling):** Совмещенная фильтрация кандидатов Top-K и Nucleus (Top-P) выполняется целиком в стековых буферах без единого вызова `malloc`.
* **Скользящее окно контекста (Sliding Window):** При заполнении лимита контекста вторая половина последовательности сдвигается в начало буфера, а векторы ключей $K$ аналитически доворачиваются на фазовый угол $-\Delta\text{pos}$ алгоритма RoPE, сохраняя математическую непротиворечивость внимания.
* **INT8 KV-Cache (`--kv8`):** Снижает потребление оперативной памяти под кэш ключей и значений на 75% по сравнению с FP32 благодаря динамическому поканальному квантованию.

### 4. Очистка опкодов MinGW CRT (`tools/sanitize_i586_pe.py`)
Современные кросс-компиляторы MinGW-w64 вставляют инструкции условного перемещения `CMOVcc` в стартовый код CRT даже при сборке с флагом `-march=pentium`. Проект включает автоматический дизассемблерный анализатор и патчер: он находит зарезервированную NOP-пещеру в секции `.text` (`__tz_i586_trampoline_cave`) и превращает недопустимые инструкции `CMOV` в безопасные прыжковые трамплины архитектуры i586, гарантируя запуск на оригинальном железе Socket 7.

## Сборка и кросс-компиляция

### Требования к окружению
* **Linux / WSL:** `gcc`, `make`. Для сборки 32-битных исполняемых файлов: пакет `gcc-multilib`.
* **Windows 98:** кросс-компиляторы `i686-w64-mingw32-gcc` и `i686-w64-mingw32-objdump`.
* **MS-DOS:** инструментарий DJGPP (`i586-pc-msdosdjgpp-gcc`).

### Основные цели Makefile

```bash
# 1. Нативная сборка под хост-систему и прогон набора автотестов
make test

# 2. Запуск интерактивного ретро-интерфейса в терминале
make tui

# 3. Сборка чистых PE-бинарников для Windows 98 (автопатчинг, 0 инструкций CMOV)
make win98

# 4. Скачивание TinyStories-260K, квантование в Q8 и упаковка автономного пакета для AMD K6-2
make k6-2-3dnow-260K

# 5. Сборка 32-битного DPMI исполняемого файла для MS-DOS через DJGPP
make dos
```

## Конвертация моделей и сборка standalone-пакетов

### Конвертация весов из HuggingFace
Любая модель архитектуры LLaMA, SmolLM или BitNet в формате SafeTensors квантуется и сохраняется напрямую в картридж `.mmx v2`:

```bash
# Квантование BitNet b1.58 из HuggingFace в тернарный картридж
python3 tools/convert_to_mmx.py --hf 1bitLLM/bitnet_b1_58-large -o bitnet.mmx -q ternary

# Инспекция метаданных и верификация контрольной суммы CRC32
python3 tools/convert_to_mmx.py --info bitnet.mmx
```

### Создание исполняемых файлов «в один клик»
Скрипт `tools/tunguzka_forge.py` позволяет объединить исполняемый файл, веса `.mmx`, словарь токенизатора и 64-байтный бинарный конфиг с трейлером `TZPK` в монолитный исполняемый файл:

```bash
python3 tools/tunguzka_forge.py \
    -m bitnet.mmx \
    -e tunguzka_3dnow.exe \
    --out-exe tunguzka_k6_bitnet.exe \
    --backend 3dnow \
    --kv8 \
    --ctx 256 \
    --steps 128 \
    --lang ru
```

## Управление в интерфейсе TUI

Текстовый интерфейс работает в классическом текстовом режиме 80x25 (через прямую адресацию видеопамяти `0xB800` в DOS, функции Win32 Console API или ANSI-эскейп-последовательности):

* **`F1`**: Окно справки по функционалу и горячим клавишам.
* **`F2`**: Циклическое переключение аппаратного бэкенда (`3DNow!` -> `MMX` -> `P54C` -> `Scalar`).
* **`F3`**: Переключение квантования контекста (INT8 / FP32 KV-Cache).
* **`F4`**: Переключение режима работы с памятью (Резидент в ОЗУ / Послойный стриминг с диска).
* **`F5`**: Сброс позиции контекста на ноль.
* **`F6`**: Смена размера контекстного окна.
* **`F7`**: Шаг температуры сэмплинга (`0.0`, `0.5`, `0.8`, `1.0`).
* **`F8`**: Смена языка интерфейса (RU/EN с нативной транслитерацией Юникод-типографики в страницу CP866).
* **`F9`**: Меню детальной конфигурации и выбор локальных картриджей моделей `.mmx`.
* **`PgUp` / `PgDn`**: Прокрутка буфера истории диалога.
* **`ESC` / `F10`**: Немедленная остановка генерации или выход из программы.
